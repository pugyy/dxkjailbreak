# 12 · 资产平面：登录前 / 登录后 / 自己开号

> 同一套站点，**登录后能拿到的信息通常是登录前的 5–10 倍**。
> 但入口判定必须从登录前做起（看他和谁集成、放开不放开注册），
> 然后**自己开号进第二层**——不靠猜。

## 一、两段的分界与铁律

| 段 | 身份 | 能拿到 | 拿不到 |
|---|---|---|---|
| 登录前 | 匿名 | 路由全集、公开 API、协议、集成、版本、错误码语义、注册流 | 用户对象、额度、签到、邀请、账单、团队、项目配置 |
| 登录后 | 普通账号 | 上面全部 **+** 14 类业务平面 | 管理员/内部面 |

**两条铁律**

1. **没号就先开号**：不要凭公开面猜登录后的结构，猜出来的字段名错一个就是几十次 400。
2. **开号是为了研究，不是为了量**：研究号 1–3 个就够，单 IP 一号、不批量。批量是注册机的活，两件事别混。

## 二、登录前：12 类公开面（不登录就能挖）

| # | 面 | 拿什么 | 怎么拿 |
|---|---|---|---|
| 1 | 前端 bundle | 路由表、接口清单、常量、默认 feature flag | 下载全部 `assets/*.js`，`grep -o '/api/[a-z0-9_/-]*'` |
| 2 | 内嵌载荷 | 首屏数据、SEO payload、初始额度表 | `grep -o '__[A-Z_]*_PAYLOAD__'`、`__NEXT_DATA__`、`globalThis.__*` |
| 3 | 公开 API 面 | OpenAPI/文档/版本化端点 | `/openapi.json`、`/v1/*`、`/docs/llms.txt`、`/.well-known/*` |
| 4 | 价格与套餐页 | 计划名、额度上限、价格、试用规则 | 价格页/FAQ/changelog/status 页全抓 |
| 5 | 注册与登录流 | 字段、验证码类型、IdP、密码规则、错误码 | 走一遍注册（不提交），看请求体与响应码 |
| 6 | 错误码字典 | 401/403/404 的语义、限流返回 | 未登录打各个端点，按 status 分桶 |
| 7 | 静态资源与构建信息 | 版本号、构建时间、源站线索 | 资源文件名 hash、`/version`、`Server`/`X-Powered-By` |
| 8 | 第三方集成痕迹 | Auth0/Authing/Cognito、Stripe/Paddle、Sentry、PostHog、Intercom | bundle 里的 key/域名、错误上报地址 |
| 9 | 子域与关联域 | 管理台、API、CDN、状态页 | `crt.sh` 全子域 + NS/MX + 证书 SAN |
| 10 | robots/sitemap/.well-known | 隐藏路径、深链配置、安全联系 | `/robots.txt`、`/sitemap.xml`、`/apple-app-site-association` |
| 11 | 客户端（APK/IPA/桌面） | 更全的接口、常量、硬编码 key | 见 `reverse-engineering` / `apk-reverse` |
| 12 | 公开分享页 | **登录后数据结构的第一手线索** | 找 `share/`、`embed/`、公开画廊、公开报表 |

**第 12 条最容易被忽略，回报最高**：公开分享页往往直接把登录后的对象结构吐出来（字段名、id 形态、嵌套关系），省掉一半猜字段的成本。

## 三、自己开号：为什么是 1–3 个而不是 1 个

| 号 | 角色 | 用途 |
|---|---|---|
| **主号** | 研究主力 | 全平面深挖，正常使用，别拿它试危险动作 |
| **探针 A** | 空白对照 | 新用户默认额度/试用期/引导流程/默认权限 |
| **探针 B** | 邀请路径 | 用 A 的邀请码注册，对比奖励、额度、绑定关系 |

**两号 diff 能直接发现四类东西**：

1. 灰度开关（同一天两个号拿到的 feature flag 不同）
2. 试用额度差异（邀请加成 vs 自然注册）
3. 默认权限差异（协作者 vs 所有者）
4. 计划差异（免费 vs 试用 vs 付费）

**开号纪律**：干净出口（住宅优先）、单 IP 一号、不同邮箱域、注册后**重新登录换 token**、先跑一次真实业务确认可用（不是 200 就算可用）。

## 四、登录后：16 个平面逐个挖

| # | 平面 | 挖什么 | 关键字段 | 验证方式 |
|---|---|---|---|---|
| 1 | 身份与权限 | 我是谁、在哪个组织、什么角色 | `me` / `role` / `scope` / `org` / `featureFlags` | 调 `/me`、`/whoami`，比对两号 |
| 2 | **额度与用量** | 剩余、上限、已用、重置周期 | `balance` / `sufficient` / `limit` / `used` / `resetAt` / `period` | 调一次真实请求再看数值变化 |
| 3 | **签到** | 奖励、连签、重置时间、幂等 | `checkin` / `daily` / `streak` / `reward` | 签一次，看幂等与输出 |
| 4 | **邀请** | 邀请码规则、奖励、绑定、上限 | `invite` / `referral` / `inviter` / `invitee` | A 邀 B，看两边账变 |
| 5 | 套餐与订阅 | 计划名、试用到期、升降级 | `plan` / `tier` / `trialEndsAt` | 查订阅接口 + 价格页对照 |
| 6 | 计费与账单 | 用量明细、单价、发票 | `usageRecords` / `invoices` / `unitPrice` | 反推单价（给反代计费口径用） |
| 7 | 支付与币种 | 渠道、币种、免费额度入口 | `paymentMethods` / `currency` | 只看配置，不发起支付 |
| 8 | API Key 管理 | 能否自建 key、作用域、过期 | `apiKeys` / `scopes` / `expiresAt` | 建一个只读 key 试权限 |
| 9 | 团队与成员 | 成员、角色、席位、协作权限 | `members` / `seats` / `collaboratorType` | `addCollaborator` 返回 null ≠ 成功，要实测 |
| 10 | 项目/工作区 | 结构、配置、环境变量、secret | `project` / `app` / `env` / `secrets` | 建一个空项目看默认配置 |
| 11 | 文件与知识库 | 上传限额、存储、分享 | `files` / `quota` / `shareLink` | 传一个小文件看返回结构 |
| 12 | 会话历史与分享 | 历史、导出、公开分享 | `conversations` / `export` / `publicToken` | 生成分享链接看是否公开可读 |
| 13 | Webhook 与集成 | 回调地址、签名、重试 | `webhooks` / `secret` / `retry` | 建一个指向自建收集器的回调 |
| 14 | 审计与登录记录 | 登录历史、设备、IP | `auditLog` / `sessions` / `devices` | 查自己的，顺带看字段模型 |
| 15 | 设置与实验 | 开关、beta、灰度 | `settings` / `flags` / `beta` | 两号对比同名字段值 |
| 16 | 内部/调试面 | admin、debug、metrics、`__dev` | 路由是否可访问 | 只做 GET 探测，记 401/403 即产出 |

**发现方法统一三招**：

1. **从 bundle 路由名反推**（`AdminXxx` / `BillingXxx` / `UsageXxx` 这类分包名就是平面地图）
2. **按名词试探**：`/api/{me,usage,quota,balance,checkin,invite,referral,billing,plans,keys,members,webhooks}`
3. **从响应里找下一跳**：任何对象里出现的 `*Id`、`*Url`、`*Token` 都是下一个平面

## 五、三个平面的专门打法

### 5.1 额度平面（做反代的人必须摸透）

```
要拿到的五件事：
① 字段语义      balance / sufficient / used / limit / period / resetAt
② 消耗速率      一次普通对话多少点，一次带工具的多轮多少点（实测取三档）
③ 归零表现      ── 关键 ── 余额为 0 通常【不报错】，而是全部请求静默超时（100s）
④ 补充规则      按日/按月重置？签到补？邀请补？充值补？
⑤ 千号合计      单号多少 × 号池大小 = 实际可用容量
```

**排查口径**：任何"突然全部失败"先查 `sufficient`，**不要先看 `balance`**，也不要先怀疑代码。

### 5.2 签到平面

```
要判的四件事：
① 触发接口      checkin / daily / signin / 签到（看 bundle 里的按钮 handler）
② 幂等性        同一天重复调用会不会重复发（正常情况下有幂等，测一次就够）
③ 连签加成      streak 是否递增奖励、断签是否清零
④ 重置时区      UTC 0 点 / 本地 0 点（直接影响你什么时候签）
```

**纪律**：只记录规则，不写批量签到脚本、不自刷邀请。刷的动作会把账号按批次带走（R-08），研究号也一样。

### 5.3 邀请平面

```
要判的五件事：
① 邀请码形态    固定码 / 每号一码 / 可枚举（自增或短 hash）
② 奖励结构      邀请人得什么、被邀请人得什么、是否双向
③ 生效条件      注册即发 / 完成首单才发 / 需对方充值
④ 上限          每日/总量/层级（二级邀请？）
⑤ 绑定关系      inviter ↔ invitee 是否落库、能否解绑
```

**风险判断**：邀请码可枚举 + 注册即发奖励 = 平台侧的漏洞（可被薅）。研究到此为止，把结论写清，不做规模化动作。

## 六、登录后挖掘的 6 条纪律

1. **只读优先**：先 GET，写操作前确认幂等与可回滚
2. **字段靠回显，不靠猜**：每个结论都要有一份真实响应作证据
3. **账号隔离**：研究号之间不共用 token、不交叉操作，避免污染对照
4. **别触发封禁动作**：批量签到、自刷邀请、高频查余额（**余额查询也有频控**）
5. **记录时间戳**：签到重置、额度补充、邀请码轮换都是时间相关的
6. **可复现**：任何结论要在第二个号上重跑一遍，两号一致才算成立

## 七、产出物

```
planes.md     平面矩阵：登录前/登录后 × 拿到/未拿到 × 证据编号
routes.json   接口全集，按"登录前 200 / 登录后 200 / 401 / 403"分桶
quota.md      额度模型：字段语义 + 消耗基准 + 归零表现 + 补充规则
growth.md     签到与邀请规则 + 时区 + 上限 + 风险判断
diff-AB.md    两号对照表（探针 A vs 探针 B，逐字段）
```

## 八、自检

```
□ 登录前 12 类面都过了一遍（尤其公开分享页）
□ 有 1 个主号 + 至少 1 个探针号，且两号做过字段 diff
□ 14 类业务平面逐个标了"拿到/未拿到/为什么"
□ 额度：字段语义、消耗基准、归零表现（静默超时）、补充规则都有
□ 签到：幂等性、连签、重置时区都有
□ 邀请：码形态、奖励结构、生效条件、上限、绑定关系都有
□ routes.json 有 status 分桶
□ 没有对平台做批量签到/自刷邀请/高频查询
```
